AI Governance & ISO 42001
What it is, and why it matters to us

Briefing for managers · Based on the AI-governance audit of 12 September 2026 (epic konvoy #6077) · Published 14 September 2026

Konvoy's engineering team uses AI assistants to help build our software. In September 2026 we audited how that use is controlled, against the international standard for managing AI (ISO/IEC 42001). The audit found that the guardrails are not yet where they should be — 13 of the 18 checks did not pass — and every gap now has a numbered ticket to fix it.

That is exactly what a first audit is for. As we go back into the sales process, customers and tender panels are increasingly asking “Do you use AI, and how do you govern it?” This page gives you the plain-English answer. Part 2 (next session) will walk through the findings and the fix-up plan in detail.

First: where does Konvoy actually use AI?

This briefing is about AI used to build our software, not AI features inside the product.

▮What we use

Engineers use AI coding assistants — principally Claude Code (Anthropic) and GitHub Copilot — to write, review and test code for Konvoy Cloud. Think of it as a very fast junior developer that works alongside a person.

▮What it can reach

The assistant works inside our code repository on an engineer's machine. It can also be connected to other tools — GitHub, Slack, Sentry, LaunchDarkly — through plug-ins. What it is allowed to touch is exactly what the audit examined.

▮What stays human

Every code change is reviewed by a person before it reaches production — the audit confirmed this control is in place and working. Our pull-request checklist already asks engineers to declare when an AI agent was used.

What is ISO/IEC 42001?

The world's first management-system standard for artificial intelligence, published December 2023.

You will already know ISO standards by reputation: ISO 9001 for quality, ISO 27001 for information security. ISO 42001 is the same idea applied to AI. It does not tell you which AI to use. It asks whether you have a system for using AI responsibly: a written policy, clear owners, a risk assessment, a set of controls, evidence that the controls work, and a habit of reviewing and improving them.

ISO 9001Quality management. “Do you make things consistently well?”
ISO 27001Information security. “Do you protect the data you hold?”
ISO 42001AI management. “Do you use AI in a controlled, accountable way?”

The standard comes with a list of 38 controls (its “Annex A”) grouped into areas such as leadership and policy, roles and responsibilities, data handling, security, transparency and lifecycle management. Organisations can be certified against it by an accredited body, on a three-year cycle with annual check-ups. Amazon Web Services, Microsoft and Anthropic all hold certification.

Two things matter for Konvoy. First, ISO 42001 is voluntary — no law requires it — but it is increasingly written into procurement and tender requirements, particularly for public-sector and large-enterprise buyers, and is widely treated as the de-facto benchmark for AI governance. Second, you can align to it without being certified. That is what we have done: we used its controls as the yardstick for an internal audit. We are not certified and must not say we are.

What the audit was

Eighteen plain-English checks, each tied to an ISO 42001 control, run against our codebase and the AI assistant's setup.

Engineering wrote a checklist of 18 rules (numbered KV-AI-01 to KV-AI-18), each mapped to a specific ISO 42001 control, and had an AI agent run them against the Konvoy Cloud repository and the environment the assistant runs in. The work was tracked as an epic with eight child issues, executed on 12 September and corrected under review over the following two days.

1Guardrails on the assistant

Is it centrally configured? Is it blocked from reading password files, sending data to the internet, or changing our cloud infrastructure by itself? Does it run in a sandbox? Rules 01–05.

2Tools it can plug into

Is there an approved list of the external tools and add-ons the assistant may connect to, and is that list written down? Are automatic checks run on what it does? Rules 06–08.

3Data hygiene in the codebase

Are there passwords sitting in the code? Is real customer or production data present where the assistant can see it? Is test data made up rather than real? Rules 09–13.

4People, process and paperwork

Do written instructions tell the assistant what it must never use? Does a human review every change? Do quality gates block bad code? Is there an AI policy at all? Rules 14–18.

Three features of how it was run are worth knowing, because they are what make the result credible to an outside reader. The audit was read-only — it changed nothing. It never read or printed a secret value; it reports file names, line numbers and pattern names only, and the report carries a formal redaction statement. And it was challenged and corrected in the open: one grade was made stricter during review (moved from “partial” to “fail”) because the rule as written demanded it, and the report records that change rather than hiding it. An audit whose grades never move under scrutiny is less trustworthy, not more.

18 rules graded. Any single “fail” sets the overall verdict to does not conform — the standard is deliberately strict.

What passed matters. The two clean passes are the ones a customer cares most about: every code change is reviewed by a person before it is merged, and engineers' local development setups do not connect to production systems. Human oversight of the AI is real, not aspirational.

What failed is mostly missing paperwork and unlocked doors, not evidence of harm. There is no written AI policy yet. There is no register of the external tools the assistant may connect to. The assistant's permission settings are permissive by default: nothing explicitly stops it reading a password file or calling out to the internet. Our automated pipeline does not scan for leaked secrets. And a handful of test-data files contain realistic-looking email addresses and phone numbers where made-up data should have been used. None of these findings says customer data was exposed; they say the controls that would prove it could not be are not yet in place.

Two items still need a human to look. A secret-scanning tool flagged 29 suspicious-looking strings across 17 files; by design the audit did not open them, so a person must confirm whether any is a real credential or (as is likely for several) a test placeholder. Separately, two very large log files on a developer machine tripped a size rule and need their contents checked. Both are assigned to the Head of Engineering.

Why this matters to Konvoy

Three reasons, in order of how soon they bite.

1. We are going back to market, and buyers will ask

“Do you use AI in your business, and how is it governed?” is now a standard line in enterprise vendor questionnaires and public tenders. A vague answer costs credibility; a made-up answer costs the deal. We can now answer with evidence: a dated audit against a recognised international standard, an honest result, and a numbered remediation plan. Very few companies our size can say that.

Why it matters: the difference between “we think we're careful” and “here is our audit” is the difference between a follow-up question and a tick in the box.

2. The risk is real, and we found it before an incident did

An AI assistant with broad access is a fast, tireless user of whatever it can reach. If nothing stops it reading a password file, it might. If nothing stops it calling out to the internet, a badly-worded instruction could send something it shouldn't. Konvoy Cloud holds customer order, pricing and location data. The audit found these doors unlocked while nobody was standing at them — which is the moment to lock them.

Why it matters: every fix on the list is cheap. The incident they prevent is not.

3. It is where the industry is heading

ISO 42001 is becoming the reference point that regulators, insurers and large customers converge on when they ask about AI — in the same way ISO 27001 became the default answer to “are you secure?”. Aligning early, while the fixes are small, is far cheaper than scrambling when a contract makes it a condition.

Why it matters: if a future tender requires certification, the path to it starts with exactly the audit we have just done.

If a customer or bidder asks you

Short, accurate answers you can give today. Stick to these — overclaiming is the one thing that would hurt us.
“Does Konvoy use AI?”
Yes. Our engineering team uses AI coding assistants to help build and test the Konvoy Cloud platform. Every change they produce is reviewed by an engineer before it goes live.
“How do you govern it?”
In September 2026 we audited our use of AI assistants against ISO/IEC 42001, the international standard for AI management systems. The audit graded 18 controls, identified gaps, and each gap is tracked as a numbered remediation item owned by engineering. We are working through them now and will re-audit when they are done.
“Are you ISO 42001 certified?”
No. We have aligned our internal audit to the standard's controls; we have not sought certification. If certification becomes a requirement for a customer, we have the foundation to pursue it.
“Does AI touch our data?”
The assistants work on our source code, not on the live customer database. Our audit specifically checks that no production data or real customer details sit where the assistant works, and the remaining items on that list are being closed out.
Please don't say: “we're compliant”, “we're certified”, or “we passed”. We did not pass, and saying otherwise in a tender is the kind of claim that gets checked. “We audited, we found gaps, we're fixing them” is both true and, to an experienced buyer, more convincing.

What happens next

Part 2 will cover this in detail. The short version:

The 13 failed rules have been turned into 14 remediation issues on the engineering board (one rule was split in two). Most are small configuration changes — adding a deny-list here, turning on a setting there. The largest single item is writing the AI governance policy itself, which is also the document that every other decision needs a home in, including the “when may the assistant act without asking?” question that the audit could not grade because no decision had ever been written down.

Once the remediation is done, the same 18-rule audit will be re-run and the result published alongside this one. The audit runbook is now committed to the codebase as a reusable tool, so a re-run is a repeatable exercise rather than a one-off project.

One decision for the business, not engineering. Should Konvoy pursue formal ISO 42001 certification? It is a 6–12 month, externally audited process with real cost, and it only makes sense if customers will ask for it. The right time to decide is after we see what the current sales round demands. This page is meant to help you spot that signal.

Glossary

AI assistant / coding agent
Software that reads and writes code on an engineer's instruction. Claude Code and GitHub Copilot are the ones we use.
ISO/IEC 42001
The international standard for an AI management system. Published December 2023. Voluntary, certifiable.
Annex A control
One of the 38 specific safeguards the standard lists. Each of our 18 rules points at one or more of them.
Aligned vs certified
Aligned means we measure ourselves against the standard. Certified means an accredited external body has confirmed it. We are the former.
Conform / does not conform
The standard's pass/fail language. One failed control means “does not conform”.
Remediation issue
A numbered ticket on the engineering board describing one fix. Fourteen were raised from this audit.
Secret
A password, API key or certificate. The audit checks these never sit in the code or within the assistant's reach.
Sandbox
A fenced-off environment that limits what software can touch or connect to, even if it tries.
