Part 1 · For the CEO & COO

The business read

Four things worth your attention, in the order they cost money.

Fuel levy is a revenue-recognition path, and it failed silently three days ago

The fuel levy has been a real line on AU and NZ invoices since 3 May, replacing a manual finance step performed on every invoice since March. On 14 August a rate-administration incident pushed four AU rate rows to a future date, leaving a window in which AU deliveries billed zero fuel levy. It was found because an operator noticed the admin page had gone blank — not by an alert.

Five of the eight resulting engineering fixes are already merged. What remains includes #5799, which reproduces the same silent-failure pattern the moment the first person is granted the new admin access, and an open Finance question about which July AU rate was authoritative.

Why it matters: this is the only workstream on the board where a defect changes what a customer is charged. Every other epic costs time; this one can cost revenue or trigger a credit note.

Writing the user documentation found twelve product defects

An engineer wrote the end-user guide by walking the product as a customer would. Doing that surfaced twelve defects — including New Collection Save doing nothing at all, in every environment, with no error message, when the chosen location has no coordinates. Also: Collections is hidden from operator Managers and Users by a navigation rule even though the backend already permits them, and an API endpoint returns every market, operator identity and SKU price to any logged-in user.

Four of those fixes are already written and waiting for review. Nothing technical is stopping them.

Why it matters: the documentation was the deliverable and the defects were the by-product — but the by-product is worth more. It is also a cheap, repeatable way to find this class of bug, and worth funding again.

Security housekeeping with a date on it

Security headers and telemetry redaction went live on 16 August in v1.89.31 and are verified in production. Two things are outstanding: a leaked sign-up-link token that remains valid until 19 August and needs invalidating this week, and a Content Security Policy that is fully specified but not started — the last real gap in that audit.

Why it matters: the token has a fixed expiry, so the cost of missing it is not recoverable by working harder next week. Roughly one to two days of work closes the whole area.

Two upgrade programmes are stalled on things we do not control

The PHP 8.5 upgrade has been audited to an exceptional standard — 42 breaking-change patterns and 41 adoption patterns, down to file and line. It is 100% blocked on a base container image in the infrastructure repository that has had no activity since it was filed and has no apparent owner. Nothing on the application side can start. Separately, the Booths Transport integration — which removes an operator re-keying every collection by hand — is nine-elevenths built but waiting on Booths to reply and on one configuration value from Marc and Alice.

Why it matters: in both cases the correct action is chasing a person, not assigning an engineer. Work already done is quietly depreciating while we wait — the Booths branch is now 39 commits behind and its test mocks predate a library migration.
